Final Design — Social Platform + LEO Activation

Complete picture. Approve each section before we write the spec.

Complete Data Flow
── WRITE: behavioral events ──────────────────────────────────────────
Flutter App → leo-cdp-framework SDK (offline-safe, auto-retry) → ArangoDB
                                                                              ↓ CDC poller (existing)
                                                            LEO Activation → Kafka → Scoring Consumer* → PG

── READ: recommendations ─────────────────────────────────────────────
Social Backend ← REST ← LEO Activation (interest scores, profile affinity, NBA, trending tickers*)

── IDENTITY: federated lookup ────────────────────────────────────────
Social Backend → phone/email → GET /identity/resolve* → profile_id

* = new additions to LEO Activation
New event types — tracked by Flutter SDK

High Signal (explicit intent)

  • social_post — posts about a ticker
  • ticker_follow — follows a ticker's thread
  • ticker_reaction — bullish / bearish / like
  • social_share — shares a ticker post
  • social_bookmark — bookmarks a post
  • discussion_comment — comments in thread

Low Signal (passive engagement)

  • ticker_page_view — {ticker, duration_ms}
  • social_feed_view — {ticker, duration_ms, position}
  • discussion_view — {ticker, thread_id, duration_ms}

Lower weight in scoring — presence alone is weak signal; duration makes it meaningful

Changes to LEO Activation (scoped)
services/scoring_consumer/

Add weight mappings for the 9 new social event types. High-signal events score higher. Duration-based events scale weight by min(duration_ms, 30000).

Existing file, new elif branches
api/identity.py (new)

Single endpoint: lookup profile_id by phone or email from PG. Used once at social login to link the two systems.

GET /identity/resolve?email= | ?phone=
api/social.py (new)

Trending tickers endpoint: aggregates social event counts from PG scoring tables, returns ranked ticker list for the social feed's "Hot Discussions" section.

GET /social/trending-tickers
What LEO Activation does NOT change
CDC poller, ArangoDB sync, Kafka pipeline, NBA/NLA engines, campaign engine, dashboard — all untouched.
Existing /recommendation/* endpoints consumed as-is by the social backend.
What the social platform owns entirely
Flutter App — UI, feed, discussion threads, posting, reactions, leo-cdp-framework SDK integration
Social Backend — post/comment/reaction CRUD, follow graph, feed ranking, push notifications, RabbitMQ async writes
Social DB — posts, comments, reactions, follows, bookmarks, shares
Identity store — maps social user ID ↔ profile_id (looked up once via /identity/resolve, cached locally)
